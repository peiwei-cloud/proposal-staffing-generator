# 標案專案人力與組織圖 Web 產生器

Streamlit 應用程式：上傳人員資料 Excel 與大頭照 Zip，即可預覽並一鍵匯出：

- **Output 1**：人員組織架構圖（.pptx，原生可編輯圖形，固定 16:9 標準尺寸）
- **Output 2**：主要工作人力配置表（.docx 表格 / .pptx 表格）
- **Output 3**：專案主要人員介紹（組長以上）（.docx）
- **✨ Gemini AI 智慧履歷潤飾**：一鍵依「擬任工作內容（JobDescription）」將組長以上人員的履歷（BioNarrative）潤飾為 200 字以內、專業精準的備標敘述。

## 卡片標頭色彩分級

- **Top / Advisor / SubTop**（計畫顧問、計畫主持人、協同主持人、次頂層）：標頭底色**鮮橙色 `#F26522`**，白字粗體。
- **Middle**（計畫經理）：標頭底色**深灰色 `#4A4A4A`**，白字粗體。
- 由 `_leader_card_header_color(row)` 依 `Layer` 動態決定，`_add_leader_card()` 套用。

## 工作組別：三層獨立卡片結構

`_add_group_block()` 已重構為由上至下堆疊三張**獨立卡片**（各自有自己的圓角外框，而非單一大外框內含多個區塊）：

1. **組名標頭條**：深灰底 `#4A4A4A` 圓角矩形，白字 11pt 粗體，顯示組名。
2. **組長獨立卡片**：自帶標頭「組長」（`#595959`，白字 9.5pt 粗體）+ 白底 1pt 灰框（`#D8DFE8`）主體；左側大頭照（0.5in）、右側姓名/職稱/徽章晶片。
3. **組員獨立卡片**：自帶標頭「組員」（`#A6A6A6`，白字 9.5pt 粗體）+ 白底 1pt 灰框主體；逐行列出「姓名 職稱」（左）＋正方形徽章晶片（右對齊）。

三張卡片之間有固定間距，`_group_block_height()` 與繪製函式共用同一組具名常數，確保試算與繪製結果一致，並已通過 50 人／8 組別極端測試驗證零重疊。

- **CV 資格抓取漏洞修復**：新增 `get_effective_badges(row)`，除了讀取 Excel `Badges` 欄位，還會掃描 `Title`／`Expertise`／`BioNarrative`／`Degree` 等 CV 相關文字欄位，比對是否提及技師科別全名（如「水利技師」），若有但 `Badges` 欄位未同步勾選，會自動補強計入統計，避免漏算。此補強**僅影響 Summary 統計數字**，不會反過來竄改 Excel 原始 `Badges` 欄位或卡片上顯示的徽章。

## 連接線視覺層次修復（不再貫穿 Summary 卡片）

- **問題根因**：主管機關 → 計畫主持人的垂直連接線，原本在程式碼中是「Summary 卡片畫完之後才畫」，而 Summary 卡片寬度（7.2in）與置中的連接線 X 座標在幾何上確實會重疊；由於連接線後畫，會直接疊加繪製在 Summary 卡片之上，造成視覺貫穿。已用座標實測驗證重疊區間確實存在。
- **修復方式**：調整繪製順序，將該連接線改為在圖例／Summary 卡片「之前」繪製。由於 PowerPoint／python-pptx 依插入順序決定圖層堆疊（後畫者在上層），Summary 卡片的不透明底色會自然覆蓋連接線經過的區域，視覺上連接線不會再貫穿卡片。
- 已用座標稽核確認：修復後連接線 z-order 位於 Summary 卡片之下，且整體版面 100% 零溢出。

## 連接線樣式與自適應

- **顏色**：改用與標頭同色系的深藍灰（`COLOR_NAVY_LIGHT`），投影時更清晰明顯（原為淺灰卡片邊框色）。
- **粗細自適應**：依安全網縮放係數 `scale` 動態調整，公式 `連接線寬度(pt) = clamp(1.75 × scale, 1.0, 2.25)`——版面寬鬆時加粗突顯層級，資料量大觸發第三層縮放時同步收細，避免密集版面線條打架。
- **卡片寬度自適應**：版面寬鬆（安全網未壓縮、分組數 ≤ 4）時，領導卡片寬度略為縮窄至 2.6in，釋放水平空間讓左右連接線更修長；資料量大時維持 3.0in 以節省空間。

## Output 1 組織圖：固定 16:9 標準尺寸 + 三層安全網

- **投影片尺寸**：嚴格鎖定 `13.333in × 7.5in`（標準 16:9 寬螢幕），不隨內容動態加高，確保匯出檔案尺寸標準相容。
- **三層安全網機制**（依序嘗試，確保 100% 不重疊、不溢出邊界）：
  1. 標準間距排版。
  2. 若總高度超出 7.5in，自動壓縮卡片間距與分組列距至最小安全值。
  3. 若仍超出，才對版面座標（卡片高度、分組區塊）做等比例縮放（縮放下限 0.7 倍），**字級全程固定 9–12pt 不受影響**。
- 已以 60 人／8 組別／每組 6 成員的極端測試資料驗證：安全網可正確觸發第三層縮放，所有卡片、徽章、連接線縮放後依然精準對齊、零溢出。

  - 「計畫經理 → 各工作組別」採主幹＋水平匯流排＋垂直分支之樹狀直角連接線。

## Layer 欄位防呆與徽章統一排序

- **Layer 大小寫防呆**：讀取 Excel 時自動去除頭尾空白並標準化大小寫（`top`/`TOP`/`Top` 皆視為 `Top`；`subtop` 視為 `SubTop`），避免使用者輸入小寫導致人員從組織圖消失。
- **全域徽章統一排序**：`["技","碩","博","品","安","採","乙","甲","景","土","水"]`，未收錄的新增證照依原順序接在最後；套用於所有卡片、圖例、Output 2/3 徽章顯示，確保全站視覺一致。
- **徽章動態選色**：`BADGE_COLORS` 未收錄的徽章代碼以 MD5 雜湊從擴充色盤（`FALLBACK_BADGE_PALETTE`）中分配固定且具鑑別度的顏色，不再統一顯示死板灰藍色，同一代碼在整份文件、每次執行皆保持同色。

## Output 3 / Tab 3 履歷抬頭格式修正

- 改用 `clean_separator_join()`：過濾空值並去除每個片段頭尾多餘的分隔符號後才串接，避免因來源欄位本身已含斜線（如 `Title='資深協理/'`）而產生 `／/` 或結尾孤立分隔符號等問題。
- 格式統一為：`計畫主持人　林金龍　資深協理／技師／碩士／採購專業人員`。

## Gemini AI 智慧履歷潤飾（含模型自動退避機制）

**API Key 讀取優先順序**：`st.secrets["GEMINI_API_KEY"]`（Streamlit Secrets）優先 → 若未設定，才使用側邊欄手動輸入的備用金鑰。

- **建議做法（部署到 Streamlit Community Cloud）**：於 App 的 Settings → Secrets 貼上：
  ```toml
  GEMINI_API_KEY = "你的 Gemini API Key"
  ```
  設定後側邊欄輸入框會自動帶入（並顯示「🔒 已從 Streamlit Secrets 自動讀取」提示），使用者不需再手動輸入，點擊潤飾按鈕也不會跳出警告。
- **備用做法（未設定 Secrets 時）**：於左側邊欄「② Gemini AI 設定」自行輸入 API Key（密碼輸入框，僅存於本次瀏覽器工作階段，不會被儲存或上傳）。

**模型選取與自動退避（Rolling Fallback）**：

- 側邊欄「Gemini 模型選取」下拉選單：`gemini-3.6-flash` / `gemini-3.5-flash` / `gemini-2.5-flash` / `gemini-flash-latest` / `自訂模型`（選中後另跳出 Model ID 輸入框）。
- 候選鏈組成方式：`[使用者選取/自訂模型] + [gemini-3.6-flash, gemini-3.5-flash, gemini-2.5-flash, gemini-flash-latest]`，自動去除重複項。
- 呼叫時依序嘗試候選模型；**僅當遇到 404 / Model Not Found 時**才無感切換下一個備援模型。
- **503 / 服務過載**：對同一模型以指數退避（1s → 2s → 4s，含隨機抖動避免同時重試）重試最多 3 次，重試仍失敗才換下一個備援模型。
- 其餘錯誤（API Key 無效、額度超限、網路逾時等）會直接中止並顯示明確錯誤訊息，不會浪費時間逐一嘗試所有模型。
- ⚠️ 官方公告 `gemini-2.5-flash` 將於 2026/10/16 起停用，建議盡快改用 3.x 系列模型；清單中保留它僅作為過渡期備援。

**使用流程**：

1. 於 Tab 3「人員經歷敘述預覽」點擊「✨ 一鍵使用 Gemini 依據擬任工作潤飾履歷」。
2. 系統會針對 Layer 為 `Top` / `SubTop` / `Advisor` / `Middle` / `GroupLeader` 的人員，將其 `Name`、`JobDescription`、`BioNarrative` 傳給 Gemini，產生 200 字以內、專業精準的備標履歷敘述，並直接覆寫 `st.session_state.df` 中對應的 `BioNarrative` 欄位。
3. 完成後會以 `st.toast` 提示「履歷 AI 潤飾完成！」（並註明實際使用的模型），頁面自動重新整理，Tab 3 與 Output 3 匯出檔案皆會反映潤飾後的最新內容。
4. 若 Secrets 與側邊欄皆未提供 API Key，點擊按鈕才會顯示 `st.warning("請先輸入 Gemini API Key")`；若單筆人員呼叫失敗，該筆會顯示警告並保留原始履歷，不影響其餘人員的潤飾結果。

## 頁尾統計數據

- **自動觸發**：Excel 上傳成功後立即自動計算，無需點擊按鈕；側邊欄另保留「🔄 重新計算」按鈕作為手動重算/還原的備用選項。
- **平均年資公式**：`df['YearsOfExp_num'].replace(0, pd.NA).dropna().mean()`，未填寫或填 0 的人員不計入分母，避免拉低團隊平均年資。
- **碩士／博士**：分開統計，僅依 `Badges` 欄位「碩」「博」代碼計算，與卡片上實際顯示的徽章晶片數量一致（不讀取 `Degree` 文字）。
- 頁尾共 5 欄：平均年資／碩士／博士／技師／專業分組。

## 字型與字級規範

- 全域中文字型統一為 **Microsoft JhengHei（微軟正黑體）**，DOCX 各段落／表格文字皆已設定 `w:eastAsia` 屬性，PPTX 亦補上對應的東亞字型設定，確保中文於各種檢視器正確顯示。
- **Output 1（PPTX）**：一般文字字級落在 9–12pt 區間。例外：頁尾醒目大數字（如「12」「13」）維持較大字級（20pt），此為刻意保留的視覺焦點設計。
- **Output 2 / Output 3（DOCX）**：文件大標題維持 16pt 加粗；表格內容與 Output 3 內文統一為 12pt（表頭／姓名列加粗）。

## 容錯設計

- Excel 缺欄位、缺值：自動補空字串／「[資料待補]」，不會導致程式崩潰。
- 照片缺失：Output 1（PPTX）與 Output 3（DOCX）皆會繪製原生可編輯的灰色預留方塊，方便後續於 PowerPoint / Word 直接「變更圖片」取代。
- Output 1 版面高度受三層安全網機制保護，人員或徽章數量增加時自動壓縮間距或等比例縮放，避免任何區塊互相重疊或溢出投影片邊界。
- Gemini 呼叫失敗會逐筆記錄警告並保留原始履歷，不會中斷其餘人員的潤飾流程。

## 已知限制／可自訂項目

- `Degree`（最高學歷科系）欄位原樣輸出，未自動切分為「校名／科系＋學位」格式，可依需求於 Excel 來源先行整理。
- 主辦機關／委辦機關名稱、團隊專業涵蓋領域為側邊欄選填文字輸入框，非 Excel 欄位。
- `Company` 欄位目前僅顯示於 Output 1 組織圖卡片，未擴及 Output 2 表格與 Output 3 敘述。
- 極端資料量（如 60+ 人、8+ 組別）觸發第三層安全網縮放時，版面會變得緊湊（卡片與間距等比例縮小，字級仍維持 9–12pt 不變）。
- 徽章全名對照表（BADGE_MAP）與排序規範（BADGE_SORT_ORDER）為範例設定，請依實際專案調整。
